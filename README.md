# PharmaQC

RAG‑сервис для сотрудников отдела контроля качества фармацевтического производства. Отвечает на вопросы по внутренним регламентам, возвращает документы‑источники и отказывается отвечать, если информации в базе нет.

Проект реализует HTTP API на FastAPI и поддерживает два движка:

- **local** — воспроизводимый BM25 RAG без внешних API; используется по умолчанию для демонстрации и измерения качества;
- **groq** — векторный поиск ChromaDB + генерация Groq LLM с проверкой дословной цитаты, retry и обработкой ошибок.

## 1. Бизнес-задача и сценарий

**Проблема:** специалисту ОКК нужно быстро найти применимое правило в нескольких регламентах и проверить его источник. Поиск вручную особенно неудобен для ситуаций, где требуется объединить классификацию, действия и сроки.

**Целевой пользователь:** лаборант или аналитик ОКК; вторичные пользователи — инженер по валидации и специалист по управлению отклонениями.

**Основной сценарий:**
1. Пользователь отправляет вопрос на русском языке в `POST /api/v1/ask`.
2. Сервис находит релевантные фрагменты пяти регламентов.
3. Ответ собирается только из подтверждённого контекста; для сложного вопроса объединяются несколько фрагментов.
4. API возвращает ответ, источники, найденные чанки и признаки `refused` / `partial`.
5. Пользователь сверяет ответ с регламентом перед принятием рабочего решения.

**Ограничения:** учебный корпус из пяти документов, русский язык, ответ только по базе знаний, решение не заменяет квалифицированного специалиста.

## 2. Подтверждённый результат

Baseline и итоговая версия запущены на **одних и тех же 10 вопросах**, одном корпусе из 61 чанка, по 3 прогона на каждую конфигурацию. Основной замер использует локальный детерминированный движок, поэтому не зависит от сети и внешней LLM.

| Метрика | Baseline | Improved | Цель |
|---|---:|---:|---:|
| Accuracy, mean / min / max | 0.50 / 0.50 / 0.50 | **1.00 / 1.00 / 1.00** | ≥ 0.80 |
| Hit@k | 0.889 | **1.000** | ≥ 0.90 |
| Галлюцинации за прогон | 3 | **0** | 0 |
| Корректный отказ на no_answer | 0/1 | **1/1** | 1/1 |
| Максимальный p95 между прогонами | 0.4 мс | **1.2 мс** | < 10 000 мс |

Условия основного замера: Python 3.12, локальный in-process вызов, 10 сценариев × 3 прогона, 1 ноября 2026. Источники: `data/eval/summary_baseline_20261101_145444.json`, `data/eval/summary_improved_20261101_145445.json`. Подробности и ограничения метода — в `docs/improvement_report.md`.

Результат независимо воспроизведён на Windows с Docker Desktop 4.97.0: контейнер перешёл в состояние `healthy`, HTTP-проверки дали 4/4 PASS, автотесты — 66 passed. Повторные три прогона подтвердили accuracy 0.50 для baseline и 1.00 для improved: `data/eval/summary_baseline_20261101_201240.json`, `data/eval/summary_improved_20261101_201241.json`. Максимальный p95 improved в этой серии — 1.7 мс; различие задержки между компьютерами ожидаемо.

**100% на десяти учебных вопросах не означает 100% качества на произвольных запросах.** Нужна отдельная проверка на расширенном наборе перед реальным внедрением.

## 3. Быстрый старт без ключей

Windows PowerShell:

```powershell
py -3.12 -m venv .venv

.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

macOS / Linux:

python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
export PHARMAQC_ENGINE=local

## 4. HTTP API

### `POST /api/v1/ask`

Запрос:

```json
{"question": "Как маркируется сырьё, находящееся в карантине?"}
```

Вопрос содержит 1–1000 символов после удаления пробелов по краям.

Ответ:

```json
{
  "answer": "2.3. Маркировка карантинного сырья: жёлтая этикетка «КАРАНТИН»...",
  "sources": ["Контроль качества сырья"],
  "chunks": [
    {
      "id": "doc_637f7a9ed8219b9a_chunk2",
      "score": 4.658,
      "document": "Контроль качества сырья",
      "text_preview": "..."
    }
  ],
  "latency_ms": 1.0,
  "refused": false,
  "partial": false
}
```

В local-режиме `score` — положительная оценка BM25, а не cosine similarity. В groq-режиме это сходство `1 - distance`.

| Код | Ситуация |
|---:|---|
| 200 | Ответ или корректный отказ |
| 422 | Пустой, слишком длинный или неверно типизированный вопрос |
| 500 | Внутренняя ошибка без раскрытия деталей клиенту |
| 502 | LLM вернула некорректный ответ после повторов (groq) |
| 503 | LLM недоступна или сервис не инициализирован (groq) |

### `GET /health`

```json
{"status":"ok","service":"PharmaQC RAG API","version":"3.0.0","ready":true}
```

`status` показывает, что процесс отвечает; `ready` — что RAG-компонент инициализирован.

## 5. Архитектура

### Local — основной воспроизводимый контур

```text
HTTP → Pydantic → BM25 retrieval → object guard → multi-query composition
     → ответ из дословных фрагментов + источники / контролируемый отказ
```

- `src/local_rag.py` загружает готовые `data/chunks/chunks.jsonl`.
- Baseline: один BM25-запрос и один фрагмент в ответе.
- Improved: дополнительные подзапросы для аспектов вопроса, до трёх фрагментов, проверка объекта вопроса, оговорка для общих правил и сравнение числового значения с допуском из документа.
- Внешние зависимости, секреты и сетевая задержка отсутствуют.

### Groq — генеративный контур

```text
HTTP → e5 embeddings → ChromaDB → top-k + threshold → Groq LLM (JSON)
     → retry/backoff → проверка цитаты в контексте → ответ + источники
```

Подробная схема, границы и обработка сбоев: `docs/architecture.md`.

## 6. Конфигурация

Основные параметры находятся в `config/app.yaml`, пресеты — в `config/presets/`, системный промпт — в `config/prompts/system.txt`.

| Параметр | Local | Groq |
|---|---|---|
| Выбор | `PHARMAQC_ENGINE=local` | `PHARMAQC_ENGINE=groq` |
| Retrieval | BM25, multi-query | e5-base + ChromaDB, top-k=5, threshold=0.75 |
| Ответ | Дословные фрагменты | `openai/gpt-oss-20b`, JSON, temperature=0 |
| Секреты | Не нужны | `GROQ_API_KEY` |
| Повторы | Не требуются | 3 попытки, timeout=30 с |

`.env.example` содержит только безопасные примеры. Реальный `.env` исключён из Git и Docker-образа. CORS выключен по умолчанию; список origin задаётся через `CORS_ORIGINS` или `api.cors_origins`.

Правила реализованы в `scripts/evaluate.py`, а не оцениваются текстовым рассуждением.

## 8. Docker и локальное развёртывание

Local-режим не требует предварительной сборки векторного индекса. Для Windows нужны Docker Desktop с WSL 2 и включённый компонент Virtual Machine Platform; отдельную виртуальную машину создавать не требуется.

```bash
docker compose up --build -d
docker compose ps
curl http://localhost:8000/health
```

В Windows PowerShell используйте `curl.exe http://127.0.0.1:8000/health`. Остановка выполняется командой `docker compose down`.

**Запуск подтверждён двумя способами:** локально через Uvicorn и в Docker на Windows. В независимой проверке образ успешно собран, контейнер `pharmaqc-api` получил статус `healthy`, `/health` вернул `ready=true`, HTTP smoke test — 4/4 PASS, автотесты — 66 passed. Полный журнал: `docs/docker_windows_transcript.txt`.

## 9. Опциональный запуск Groq

1. Установите `PHARMAQC_ENGINE=groq` и действительный `GROQ_API_KEY` в `.env`.
2. Соберите индекс после изменения документов или чанкинга:

```bash
python main.py && python chunk.py && python embed.py && python index.py
```

3. Запустите Uvicorn или `docker compose up --build`.

При первом запуске скачивается `intfloat/multilingual-e5-base` (около 1 ГБ). Качество groq-режима нужно измерять отдельно тем же `scripts/evaluate.py`; метрики local-режима не переносятся на LLM.

## 10. Ограничения и развитие

- Корпус содержит пять учебных регламентов; это не полноценная GMP-система.
- Local-режим использует лексический поиск и набор доменных intent-правил; сложная перефразировка и новые типы рассуждений требуют новых тестов.
- Проверка объекта намеренно консервативна и может отклонить корректный нестандартный вопрос.
- Оценка фактов основана на заранее заданных группах; для внедрения нужна независимая экспертная разметка.
- Groq-режим зависит от внешнего API; его реальная точность и сетевая задержка в этой среде не измерялись.
- Дальнейшие шаги: расширить набор до 50–100 вопросов, добавить гибридный reranker, версионирование документов, авторизацию и мониторинг.
