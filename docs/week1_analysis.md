# Анализ и планирование

Документ фиксирует исходную постановку и выбранную траекторию. Актуальные параметры и результаты — в `README.md`, `docs/requirements.md` и `docs/improvement_report.md`.

## 1. Бизнес-задача

Сотруднику ОКК фармацевтического предприятия нужно находить применимые правила во внутренних регламентах и проверять первоисточник. Для многошаговой ситуации требуется объединить несколько пунктов: класс отклонения, первые действия, срок регистрации и срок расследования.

Проектная гипотеза: ассистент сокращает время поиска и снижает риск использования нерелевантного правила, если отвечает только по корпусу и явно отказывается при отсутствии данных. Численная оценка экономии времени в рамках учебного проекта не проводилась.

## 2. Пользователь и сценарий

**Основной пользователь:** лаборант/аналитик ОКК.

**Вторичные пользователи:** инженер по валидации, специалист по управлению отклонениями.

**Сценарий:** пользователь задаёт вопрос через HTTP → получает ответ с источниками → проверяет исходный регламент → принимает решение самостоятельно.

## 3. Ограничения

- Пять учебных документов, русский язык.
- Нет доступа к реальным персональным или производственным данным.
- Нельзя использовать внешние знания как основание ответа.
- Обязательны контролируемый отказ и обработка ошибок.
- Сервис не заменяет специалиста и не является автоматизированной GMP-системой решений.

## 4. Выбранная траектория

**RAG — корпоративный Q&A-ассистент.**

Направления доработки:

1. Мультизапросный retrieval для вопросов, требующих нескольких фрагментов.
2. Консервативный порог/правило отсечения вопросов об объектах, отсутствующих в базе.
3. Доработка правил ответа строго по контексту, включая `general_rule` и `no_info`.
4. Дополнительно: воспроизводимый local-режим, чтобы сравнение не зависело от недоступной внешней LLM.

## 5. Исходный baseline

Исходный архив содержал Groq baseline с результатом 5/10, но последующая корректировка эталонов изменила часть сценариев. Поэтому для корректного итогового сравнения зафиксирован отдельный исполняемый local baseline: один BM25-запрос, top-k=3, один фрагмент в ответе, без защитных правил.

Исторические файлы сохранены в `data/eval/archive_before_fixes/`, но не смешиваются с итоговой таблицей.

## 6. Критерии успеха

- Accuracy ≥ 0.80 на 10 фиксированных вопросах.
- Hit@k ≥ 0.90.
- Ноль галлюцинаций и корректный отказ на no_answer.
- p95 < 10 секунд.
- Нет критического ухудшения других показателей.
- HTTP API, конфигурация, логирование, тесты и локальное развёртывание воспроизводимы по README.

Итоговые значения и доказательства приведены в `docs/improvement_report.md`.
